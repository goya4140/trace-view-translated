# Model-free trace 语义反编译（实验版）

这一视图只使用本地 trace 数据和确定性规则，不调用总结模型。原始 JSON 仍由 Inspector 按需读取。

## 数据路径

1. Provider adapter 把 JSONL 归一化为 `TraceEvent`，并保留原始文件位置。
2. `web/src/translation.ts` 将事件归入用户轮次；开场规则和注入上下文不会被当作提问。
3. `web/src/semantic.ts` 配对工具调用与返回、识别命令意图，再聚合为查找、分析、判断、写入、检查等阶段。
4. `SemanticView` 展示每个阶段的证据事件 ID；点击后由 Inspector 打开原始记录。

## 证据约束

- **工具记录**：表示 trace 确实记录了某次调用或文件变更。命令返回成功只证明该检查没有报告失败。
- **Agent 的说法**：从助手消息中摘录，并明确标记为未经程序独立证实。
- **尚未解释**：没有匹配规则的工具调用仍显示数量和证据，不编造目的。
- **失败尝试**：从工具错误、非零退出码或明确的失败输出识别；其后的工作单独判断。

阶段会合并同类操作，适合阅读任务过程；精确时间顺序仍以原始轨迹为准。

## 扩展规则

在 `classifyCommand` 中增加可识别的命令模式，或在 `classifyCall` 中增加 provider/tool 规则。新规则应返回阶段类别和简短动作，并为成功、失败、未知输入编写测试。`exec` 包装器只读取可静态识别的命令参数，不执行 trace 中的代码；复杂动态参数会落入“尚未解释”。
